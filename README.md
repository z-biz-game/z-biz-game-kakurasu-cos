# 数和 · KAKURASU

数和格（Kakurasu）：一个 0/1 棋盘，每行、每列各带一个**带权**和的线索。
行线索 = 这一行里被选中格子的**列号**之和；列线索 = 这一列里被选中格子的**行号**之和。
把每行每列的和都点准确，盘面就解开了 —— 而这一局**只有一个**解，这是算出来的，不是标的。

```
4 × 4   行线索 6 6 9 4   列线索 3 6 6 7        （权重：行号 / 列号）
        ┌───┬───┬───┬───┐
      6 │ ■ │ ■ │ ■ │   │   1+2+3 = 6 ✓
        ├───┼───┼───┼───┤
      6 │ ■ │ ■ │ ■ │   │   1+2+3 = 6 ✓
        ├───┼───┼───┼───┤
      9 │   │ ■ │ ■ │ ■ │   2+3+4 = 9 ✓
        ├───┼───┼───┼───┤
      4 │   │   │   │ ■ │   4 ✓
        └───┴───┴───┴───┘
        列 3=1+1+1 ✓   6=2+2+1+1 ✓   6=3+3 …
```

## 玩法

* 点一格 = 选中它（立刻计入所在行/列的带权和）；再点 = 取消。
* 顶部与左侧各有两个数字：**线索**（金色，满了变青）与**当前带权和**（灰色）。
  某行的和**超过**线索时数字变红 —— 权重都是正数，超了就回不来。
* `标记` 按钮（或 `n` 键）切到划叉模式：划掉的格子不计入任何和，只是给你自己留的记号。
* `撤销` `u` · `提示` `h` · `重开` `r`。提示只说**纯推理能证明**的格子；如果它说"要假设了"，
  那是求解器实测出来的 `depth`，不是它懒得想。
* 完成判定：所有行/列带权和都等于线索，**且**盘面与那个被证明为唯一的解逐格相同。
* 成绩存在本机浏览器，清空要点两次。

## 屏上的数字是谁算出来的

| 屏幕上 | 谁算的 | 怎么复现 |
| --- | --- | --- |
| `解数 1` | `js/core/count.js` 两条互相独立的计数器：逐行子集 DP + 逐格回溯，都数到 2 就停 | `node test/lots.test.mjs`（对每一关重算两遍） |
| `推理 409`（= 深度×100 + 轮数） | `js/core/logic.js` 那个确定性求解器实测：假设层数与传播轮数 | `node tools/bake.mjs`（从序列化线索对重算，对不上就构建失败） |
| `最少 N 点` | 唯一解的格子数；每点只改一格 → 没有更短的路 | `node test/game.test.mjs`（真跑了 2^16 状态 BFS 反证） |
| 难度带 1 / 2 / 3 / 4+ | `tools/bake.mjs` 从实测 rank 分布切的四刀，每刀都要求该尺寸**填得满** | `node tools/bake.mjs` 的 `[2/4] ladder/fill` 两行 |

外部锚点（不是本仓的实现，是它对得上公开事实的地方）：把 4×4 的全部 `2^16 = 65536`
个棋盘按 `(行线索, 列线索)` 归类 ——

* 各类大小之和恰为 **65536**（每格棋盘只落进一个桶）；
* 类数 **64959**，且由两条独立数法（按棋盘枚举、按行子集四重积构造）各自算出同一个数；
* 其中 **64382** 类唯一解、**577** 类多解（且多解类的大小都恰好是 2）；
* 抽查 **400** 个类，DP、回溯、穷举三条路给出同一个数。

```bash
node test/anchor.test.mjs     # 上面四条，期望值是手写在测试里的
node tools/bake.mjs           # 出题 + 复验，并把这些数字再印一遍
```

耗时（本机 2026-09-27，机器负载 ~30，结构量逐位可复现，计时量随机器漂移）：
anchor 测试 < 2s；`bake` 全量 40 关约 3.5 分钟，其中 96% 花在 6×6/7×7 的线索极小化上。

## 跑起来

```bash
node server.cjs          # http://127.0.0.1:5192/  —— 零依赖静态服务器
npm run check            # node --check 全量（与 CI 的语法步骤同一文件集合）
node --test test/        # 8 个 node 测试文件
bash tools/verify.sh     # node 层 + 一次真实 headless Chrome 的 6 段浏览器断言
npm run bake             # 重新出题（会改写 js/data/lots.js）
```

零依赖、零打包器、零图片素材：`dependencies` 与 `devDependencies` 都是 `{}`，画面全部由
canvas 2D 程序绘制。ES module 需要 origin，所以双击 `index.html` 不是支持的玩法。

路由：`#/c/<n>` 战役 · `#/lot/<id>` 分享某一关 · `#/daily` 当日题 · `#/random/<band>/<token>` 现场生成。
`#/daily` 从 `hashSeed(YYYY-MM-DD)` 落在**题库**的下标上 —— 同一天所有设备同一局，且页面加载时
不做任何搜索。`#/random` 才会现场跑生成器，且被 `MAX_ATTEMPTS` 与计数器的节点上限夹住。

## 已知边界（诚实清单）

* **规格里那条"抹掉任一条线索后解数必须 ≥2"，在 数和 的完整线索集上做不到**，而且不是"还没调好"：
  4×4 抽 1200 个唯一解类，逐个抹掉 8 条线索中的任一条，解数**全部仍是 1**（0/9600 条线索是
  load-bearing 的），并用独立的 2^16 穷举复核过。8 条精确带权和压 16 个二元未知数，本就过定。
  本仓因此把这条反证搬到**线索的 inclusion-minimal 核心**上（贪心可删到哪一步、剩下的每条
  线索是否都咬得住），并把 `coreSize` 与 `coreStatus` 一起印在数据里 —— 详见 `DESIGN.md` §2.4。
* 4×4/5×5/6×6 的随机唯一题面在"单行子集排除"这个强度的求解器下 `depth` 实测恒为 0；
  需要假设的题面（`depth ≥ 1`）目前只出现在 7×7。所以小盘的难度带用的是 `chains`。
* 不做 8×8 及以上：DP 的状态是列部分和向量，随 c 组合爆炸。
* 6×6/7×7 的线索极小化在 bake 的算力预算内常常只能给出 `coreStatus: 'bounded'`（上界），
  这类行的 `coreSize` 是**上界**而不是精确值，数据里逐行标出来了，测试也按这个口径断言。
* 没有成就、排行榜、签到、内购、云存档；分享的只有谜题本身（`#/lot/<id>`）。
